# OHCP 农作物缺素症智能体前端开发计划书

日期：2026-10-21｜状态：设计稿，尚未开始业务开发

## 1. 目标与依据

使用简单的 Vue 3 前端，完整演示“输入症状 → 识别缺素 → 查看科学施肥建议 → 继续追问”，同时覆盖架构文档涉及的知识科普、统计看板、服务自检与知识重载入口。

依据两份文档：

1. 《OHCP农作物缺素症识别与科学施肥建议智能体需求文档V1.0》：确定核心功能、知识库证据、绿色农业提示和可运行交付要求。
2. 《农作物缺素症智能体-前后端对接架构设计》V1.0，2026-10-21：确定 `/api/v1` 接口、三类诊断结果、六段式方案及 SSE 事件。

用户已选择“首版覆盖架构文档全部页面”。文档没有规定必须有几个页面，本计划将这些能力组织为三个主页面和一个抽屉，减少页面跳转。图片识别在原文中属于创新扩展，目前只有 `imageUrl` 字段，没有上传接口，因此不计入首版必交范围。流式追问及农户／专业双模板作为首版创新展示。

原始需求的评分表以图片形式存在，本次文本转换未解析其中细项；验收依据正文明确列出的要求，不推测图片评分分值。

## 2. 简单技术方案

| 项目 | 选择与用途 |
| --- | --- |
| 应用 | Vue 3 + Vite，使用单文件组件与 `<script setup>` |
| 语言 | TypeScript，仅定义接口 DTO、表单及状态，不引入复杂泛型 |
| 导航 | Vue Router，使用 Hash 路由，便于随 Spring Boot 静态资源部署 |
| 界面 | Element Plus：表单、卡片、表格、抽屉与提示；少量普通 CSS |
| 请求 | 原生 fetch；普通 JSON 请求和 SSE 共用错误处理与取消能力 |
| 状态 | 页面内 ref/computed，诊断与对话逻辑放 composables；首版无需 Pinia |
| 图表 | 热门查询用表格及 CSS 条形图，无需额外图表库 |
| 测试 | Vitest 测关键传输和状态逻辑，浏览器人工验证完整流程 |

页面只展示后端返回的候选、置信度、证据和施肥内容，不调用模型、不计算缺素结论、不自行生成施肥剂量。置信度只作百分比格式化，不另算业务等级。

开发时浏览器访问 5173，Vite 将 `/api` 原路径代理到 `http://localhost:8080`，保留 `/api/v1` 前缀。交付时将 `dist` 内容复制到 Spring Boot 静态资源目录，由 8080 同源提供页面和接口。前端 `.env.example` 仅记录代理目标、Mock 开关等公开配置，不放模型密钥。

技术参考：[Vue 官方快速开始](https://vuejs.org/guide/quick-start)、[Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview)、[Vite 代理配置](https://vite.dev/config/server-options)、[Vite 静态部署](https://vite.dev/guide/static-deploy)。具体稳定依赖版本及 Node 兼容版本在脚手架阶段核对并写入锁文件与 README。

## 3. 页面与交互

### 3.1 智能诊断页 `/#/`

桌面端左侧输入、右侧结果，手机端纵向排列。采用白底、绿色主色、清晰字号与较大的按钮，重点突出“开始诊断”和结果。

- 必填：作物 `crop`、症状描述 `symptomText`（8～500 字）。提供水稻老叶发黄示例，一键填入但不自动提交。
- 折叠补充项：部位 `part`、叶龄 `leafAge`、环境 `env`（最多 200 字）、土壤 `soil`、生育期 `stage`；未填写的可选项不发送。
- 输出模板：农户版 `farmer` 默认，专业版 `pro` 可切换。
- 确认结果：最多显示前三项候选、后端置信度、匹配特征及证据折叠区。默认选择后端排序第一项，不自行重新排序。
- 施肥方案：缺素名称、简介、农艺调控、有机／生物肥、化学施肥、安全减量提醒。肥料表同时可查看方法、养分含量与注意事项，避免只展示三列而丢失安全信息。
- 切换候选或模板，只重新请求施肥方案，不重新诊断。加载时保留诊断结论，旧方案明确标识正在更新；失败时提供局部重试。
- 补充追问：按后端 `followUp.question/options` 显示问题和按钮，将选择写入白名单内的 `expectedField` 后重新诊断，保留其余输入；未知字段不盲目写入表单，提示补充描述并记录联调信息。
- 无匹配：显示后端补充建议与农技咨询引导，不显示确定性结论和施肥用量。
- 流式聊天：在结果下方显示消息列表与追问输入，携带后端 `sessionId`；发送中可停止，结束后解锁输入。
- 科普入口：候选旁“了解更多”打开知识抽屉，请求对应元素条目；加载失败不影响已有诊断。
- 绿色农业引导：结果底部显示一至两行短句，与科学施肥相关；优先使用后端内容，不单独弹窗，不编造人物事迹。

### 3.2 知识科普页 `/#/knowledge`

用元素按钮切换 N、P、K、Mg、Fe、Zn、Ca、B、Mn、Cu、Mo、S，调用单元素知识接口展示条目、症状和可用来源。作物适配范围及施肥内容以返回数据为准；无条目显示空态，不生成替代知识。与诊断页抽屉复用 `KnowledgeCard`。

### 3.3 统计与服务页 `/#/dashboard`

- 热门查询：表格或条形图展示后端统计，提供刷新按钮；统计周期、计数单位和排序由后端契约决定，不用前端演示数据冒充真实统计。
- 服务自检：显示后端实际提供的服务及依赖状态，页面加载和手动刷新时检查；首页也执行一次轻量自检。
- 知识重载：作为维护操作入口，点击后二次确认、执行中禁用按钮，结束后刷新服务状态及当前知识内容。后端若要求权限，按契约隐藏或禁用，不在浏览器保存管理密钥。
- 服务检查失败只显示状态及重试入口，不清空已有诊断，也不把健康检查通过当作所有业务接口可用。

## 4. 接口对照与必须补齐的契约

| 接口 | 前端用途 | 当前文档情况 |
| --- | --- | --- |
| `POST /api/v1/diagnose` | 提交表单、补充字段再诊断 | 请求较完整；完整响应 DTO 缺失 |
| `POST /api/v1/advice` | 切换元素／模板获取方案 | 已说明 crop、element、mode；方案子对象字段名缺失 |
| `POST /api/v1/chat` | 流式追问 | 已定义事件名；请求体及部分事件包装缺失 |
| `GET /api/v1/knowledge/{element}` | 科普页与抽屉 | 只有路径，响应字段缺失 |
| `GET /api/v1/stats/hot` | 热门查询 | 统计周期、字段及响应结构缺失 |
| `GET /api/v1/health` | 首页检查及服务状态 | 依赖状态、能力标识和响应结构缺失 |
| `POST /api/v1/knowledge/reload` | 维护入口 | 请求、响应、权限及同步／异步语义缺失 |

正式编码前由前后端一起补齐 OpenAPI 和 `examples/`；前端可以先用明确标记的 Mock 样例做界面，真实联调前必须冻结以下内容：

1. 作物枚举：原文引用“作物枚举”但未给取值，不能把前端示例作物当成后端已支持清单。
2. 诊断响应：`requestId`、`decision`、`candidates` 完整成员、匹配特征、证据、`followUp`、降级结构及会话标识；确认首个方案是否内嵌。本计划默认诊断完成后调用 advice 获取方案。
3. 方案 DTO：`organicPlan` 与 `chemicalPlan` 每个子字段的准确名称和类型、用量是否已含单位；统一 kg/亩，不由前端换算或补造剂量。
4. 聊天请求：问题字段、上下文关联方式、`sessionId` 的生成者及最大长度；`meta` 首帧究竟使用统一响应包装还是直接携带事件数据，各事件均需可执行样例。
5. 知识、统计、健康、重载四个接口的完整 DTO、错误样例和权限。未返回来源时不伪造来源；缺字段时显示“未提供”。
6. 降级规则：原文同时出现 `isDegraded`、`data.degraded` 和数字级别，需统一字段及级别含义。界面区分模型简化、规则检索等模式，不将所有降级都称为“离线”。
7. 错误规则：统一响应 `code/message/data/traceId/costMs`；明确 2002 的实际包装。建议无匹配、模型降级均返回 `code=0`，使用 decision／degraded 表达；若现有实现使用其他包装，在请求层集中适配，不能被普通错误拦截吞掉。
8. 重试规则：原文一处规定 2001 三秒后重试，另一处说仅 5000／超时自动重试，存在冲突。建议把 2001 作为一次重试特例，5000／超时仅对确认可安全重放的读取及诊断操作重试一次；聊天和知识重载不自动重放，防止重复会话或重复执行。

以上为对齐清单与建议，不代表后端已经实现或同意。无法确认的接口可先保留 Mock 展示，最终验收必须标明真实联调缺口。

## 5. 请求、状态与异常

- 页面主状态使用 `idle / loading / confirmed / asking / empty / error`；文档中的 submitting 与 analyzing 合并为一个加载态，减少无意义的状态切换。降级是额外标记，可与结果并存。
- 普通 JSON 请求超时 15 秒。发送后禁止重复点击；换作物或发起新诊断时取消旧请求，旧响应不得覆盖新结果；方案切换也检查请求身份。
- `1001` 定位字段，缺少字段定位信息时保留输入并显示表单级提示；`1002` 重置被明确指出的非法选项；`1003` 提示字数上限。`4001` 提示频繁操作并在 5 秒后开放重试。
- 网络失败与 `5000` 显示重试卡片，保留输入；错误提示使用前端中文映射，不直接展示开发者 message 或堆栈。有 traceId 时显示后 8 位，没有时不显示虚构编号。
- 可选空值显示“未提供”，空数组显示“暂无内容”；核心字段缺失则提示响应异常，避免渲染伪造结论。忽略新增字段；未知枚举可显示安全文本，未知 decision 显示无法解析结果及重试入口。
- 用户输入、模型文本及来源标题均按普通文本渲染，不直接 `v-html`。来源链接仅允许 http/https。模型密钥与知识重载凭据均不进入前端构建产物。

SSE 使用 POST fetch + ReadableStream，而非 EventSource。解析器保存未完成帧，支持 UTF-8 跨块解码、LF／CRLF、多行 data 及任意网络分块；按 event 分发 `meta/candidate/token/sizheng/done/error`，静默忽略 ping 和未知事件。

`token.delta` 逐段追加到当前聊天气泡，不覆盖结构化施肥表格。`done` 解锁输入；流内 error、提前断流和用户停止都保留已收到文本并标注状态。切页和重置会话时取消流，不自动续传或重发 POST。首帧与空闲超时建议各 15 秒，合法事件／心跳重置空闲计时，不能在总时长 15 秒时截断正常长对话；该差异需要和后端共同确认。首字 1.2 秒是联调体验目标，需实测，不由前端承诺模型性能。

## 7. 分阶段开发安排

以下为接口样例齐备后的单名前端开发者有效工作量估算，总计约 2～3 个工作日；后端补契约及等待时间另计。全范围不应承诺一小时现场从零完成，一小时比赛应提前准备可复用基础和样例，现场优先演示核心闭环。

| 阶段 | 工作内容 | 交付与验证 | 估算 |
| --- | --- | --- | --- |
| 1. 基础与契约 | 冻结 DTO／样例，初始化 Vue、路由、组件库、代理和 Mock | 三个页面能导航；Mock 模式有显著提示；锁文件与公开配置样例齐备 | 0.5 天 |
| 2. 诊断闭环 | 表单、多候选、证据、三类结果、六段方案、模板切换和补充字段 | 成功／追问／无匹配／降级样例均可操作；候选与模板快速切换不串结果 | 0.5～1 天 |
| 3. 全部功能入口 | 流式追问、知识页与抽屉、热门统计、健康检查、知识重载 | SSE 可结束／取消／处理断流；每个辅助接口都有成功、空态及失败展示 | 0.5～1 天 |
| 4. 真实联调与交付 | 替换真实接口、检查移动端、补关键测试、构建与启动文档 | 真实后端完整演示；静态资源同源部署验证；README 可复现启动流程 | 0.5 天 |

实施阶段先检查分支、工作区与主分支基线，创建独立任务分支；依赖前一任务未合并时基于其分支并说明。每个任务通常按核心实现、边界验证、文档交付等真实阶段提交 2～6 次，简单不可拆分任务一次提交即可；不混入其他改动，不直接在 main 开发。

推荐按上述阶段安排内聚提交，例如 `chore: 搭建 Vue 前端与契约样例`、`feat: 完成诊断及施肥建议闭环`、`feat: 增加流式追问与辅助页面`、`test: 完成联调边界验证及启动说明`；若某阶段范围变大，应拆任务而非堆积大提交。
