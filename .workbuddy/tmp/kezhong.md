> **适用范围**：本学期开设的课终小组项目  
> 覆盖课程：「面向对象程序设计」「大数据处理技术」两门课程的课终环节
>
> **文件状态**：V0.2 已确认  
> **最后更新**：2026-10-13

---

## 一、评分档位（核心机制，一句话先看）

本学期课终项目评分采用**三档制**：

| 档位  | 分数范围         | 触发条件            | 给分主体   |
| --- | ------------ | --------------- | ------ |
| 基础档 | **75**       | 提交项目 + 通过 AI 评测 | 自动判定   |
| 答辩档 | **80 – 95**  | 在基础档基础上报名参加分享答辩 | 任课教师打分 |
| 案例档 | **95 – 100** | 项目入选课程案例库       | 任课教师打分 |

**关键说明**：

- 三档是**递进关系**：拿到答辩档的小组一定拿过基础档；拿到案例档的小组一定拿过答辩档与基础档
- **不答辩就只能停在基础档 75 分**——这是为了区分「主动展示型」与「被动提交型」
- 答辩档与案例档的**具体分数由任课教师综合判定**，本规则仅规定区间，不做硬性细颗粒度切分

## 二、各档达成路径与判定细则

### 2.1 基础档（75 分）

#### 必交材料

1. **源代码仓库**（含 `README.md`、依赖清单、构建与运行说明）
2. **答辩 PPT**（结构清晰，能讲清「需求 / 方案 / 数据 / 关键结果」四项基本要素）
3. **可复现的运行产物**（部署文档 / 演示视频 / 运行截图三选一）

#### AI 评测规则（教师侧脚本自动审查）

| 检查项      | 必备条件                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 代码可编译可运行 | 按 `README.md` 操作，主流程不出错                                                 |
| 依赖清单完整   | Java 项目须含 `pom.xml`/`build.gradle`；Python 项目须含 `requirements.txt` 或等价文件 |
| 文档齐全     | 含项目说明、目录结构、关键功能模块说明                                                     |
| PPT 要素完整 | 含项目背景、方案/架构、数据/输入、关键成果                                                  |
| 无明显抄袭特征  | 教师侧单独巡检                                                                 |

通过 AI 评测即得基础档 **75 分**。

#### 不通过的处理

- 轻度问题（如缺少截图）：打回修改，给一次补交机会
- 严重问题（如无法运行、关键缺失、AI 代写痕迹明确）：判定本次提交无效，本学期不予基础档分数

### 2.2 答辩档（80 – 95 分）

在基础档基础上，**小组自愿报名**参加分享答辩。教师依据答辩表现给定具体分数。

#### 教师评分参考维度

> 教师可结合课程特点调整权重，不需要每次都做。

| 维度     | 参考权重 | 释义                       |
| ------ | ---- | ------------------------ |
| 项目完成度  | 30%  | 是否做出实际可用的成果 / 是否仅停留在方案设计 |
| 技术深度   | 30%  | 分析模型是否严谨 / 系统设计是否合理      |
| 现场表现   | 25%  | 演讲结构清晰度 / 质询环节应答准确性      |
| 工作量与创新 | 15%  | 工作是否饱满 / 是否有创新性尝试        |

#### 分数参考刻度

- **80**：达成基础要求，演示完整
- **85**：达成良好，演示流畅
- **90**：达成优秀，模型 / 设计有亮点
- **95**：达成极优秀，已达案例库入库水准

#### 特别说明

- 同一小组在同一答辩环节中分数唯一，教师一次性给定
- 不同小组分数可不平均，由教师综合判定
- 答辩时间未到 / 已请假缺勤：保留基础档 75 分，不补答辩

### 2.3 案例档（95 – 100 分）

在答辩档基础上，项目经课程组评审**入选课程案例库**，由教师给定具体分数。

#### 入库硬性条件

- 项目具备明确的应用场景或可复用的方法论
- 文档规范完整、可作为下届学生学习参考
- 已通过答辩并获 ≥ 90 分

#### 分数参考刻度

- **95**：勉强入选
- **98**：入选作品中的上品
- **100**：本课程该学期的最高水平

## 三、答辩环节说明（两门课程的差异）

| 课程           | 答辩安排                       |
| ------------ | -------------------------- |
| **面向对象程序设计** | 本学期**只设期末答辩一次**（不单独组织期中答辩） |
| **大数据处理技术**  | 课程包含**期中答辩 + 期末答辩两个环节**    |

**关键说明：「答辩不再作为必须环节」解读**

- 面向对象程序设计课程/大数据处理技术课程：答辩**仍是取得高于基础档成绩的必要条件**（即不答辩就停在 75 分）
- 面向对象程序设计课程/大数据处理技术课程：答辩**不再是必要条件**，学生可以只拿基础档 75 分结题
- **两次答辩评分完全独立、互不合并**：期中答辩与期末答辩分别单独评分、独立归档，**不做平均、不取较高、不加权求和**。同一次答辩中分数唯一

#### 推荐安排（仅供参考，可调整）

| 时间点       | 大数据处理技术     | 面向对象程序设计 |
| --------- | ----------- | -------- |
| 学期第 8 周前后 | 期中答辩（如选择参加） | —        |
| 学期最后一周    | 期末答辩        | 期末答辩     |

## 四、其他约定

### 4.1 诚实参与原则

- 评分以项目真实性为基础
- 发现抄袭、AI 代写等学术不端行为，按学校相关规定处理
- 已给分数一律撤销，必要时通报课程组

### 4.2 分数异议

- 评分公示后 **3 个工作日内**可提出申诉，逾期不受理
- 申诉由课程组集体复议，结果为最终结论

### 4.3 案例库管理

- 入库评审由课程组集体决定，结果通过课程平台公示
- 入库作品须附带一份「学习指引」文档，方便下届学生上手
