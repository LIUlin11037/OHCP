# OHCP 项目长期记忆

## 角色分工（已确认）
- 用户：学生小组一方，负责提供题型/技术文档、对外答辩
- 我：**主要负责写代码**。技术文档由用户后续发来，在此之前不擅自开工造骨架。

## 评分锚点（写代码时始终对齐）
OHCP §5.1 六维度，权重按高低排序：
1. 需求思考与完成度 20%
2. Harness 过程与架构合理性 20%
3. 系统亮点 20%
4. 功能测试覆盖率 15%
5. 演讲材料质量 15%
6. 人员分工合理性 10%

→ 合计 55% 押在「可跑 + 可测 + 结构清」，40% 押在「需求覆盖 + 亮点」。
→ Harness 单列 20%，说明教师重视**过程证据**（测试驱动痕迹），不只是结果。

课终项目（另一套）：完成度 30 / 技术深度 30 / 现场表现 25 / 工作量与创新 15。

## 编码约定（因评分维度反推）
- 核心逻辑纯函数化、与 IO 解耦 → 好测 + 解耦可见
- 每个需求点必须有对应测试，用例命名映射需求编号
- README 一条命令可跑通（这是基础档入场券）
- 亮点在开发前期埋，不留到最后
